> 记录本次会话从「解析 robomaster.com/live」到「实现并迭代打磨一个可用的多视角直播间」的完整过程、技术结论与踩坑。

## 0. 目标

把 RoboMaster 官方直播页 `https://www.robomaster.com/live` **解析**清楚，并**重做**一个多视角直播间：
- 消费它的**直播推流**（舍弃「主视角无解说版」和「红/蓝机器人合集」两路）。
- 复刻它的**弹幕聊天室**（每条弹幕含：十周年徽章、学校、身份标识、正文），并支持自填身份发送。

最终成果：一个**纯前端 React + Vite + TS 应用**，对接真实直播流与真实 LeanCloud 弹幕，已实测可用。

## 1. 网站解析结论（逆向）

工具：先用 Chrome 浏览器工具抓包，后改用 **Python + Playwright**（能抓 WebSocket 帧、绕开输出过滤）。逆向脚本与产物都在 `recon/`。

整个站点是 **Nuxt（Vue SSR）单页应用**，由两条独立数据通道驱动，且**三处都跨域开放（`Access-Control-Allow-Origin: *`），因此整套可纯前端实现、无需任何代理**。

### 1.1 视频推流（HLS）
- 协议：HLS（`.m3u8` + `.ts`），走大疆 CDN `rtmp.djicdn.com/robomaster/<流名>.m3u8`，URL 带阿里云 A 型鉴权 `auth_key`（**服务端签发、长效**）。
- **流目录全部来自一个静态文件**：`rm-static.djicdn.com/live_json/live_game_info.json`
  - `eventData[]` = 赛区数组，每个赛区含：`zoneName / liveState / matchState / chatRoomId / zoneLiveString / fpvData[]`。
  - **当前直播赛区** = `liveState === 1` 的那个（其余为已结束赛区）。
  - **主视角**：`zoneLiveString[]`（3 档源）→ 流名 `fight2026-output`。
  - **机位**：`fpvData[]`，每项 `{ role(视角名), headimg, sources:[{label,res,src}×3] }`。
  - **清晰度 = 独立 URL**（非 master 多档）：`1080p=<base>.m3u8`、`720p=<base>_ud.m3u8`、`540p=<base>_hd.m3u8`。切清晰度 = 换 source URL。
  - **取舍按 `role` 名过滤**：含「合集」或「无解说」→ 丢弃。某直播赛区 13 路 fpv → 保留 10（红5+蓝5）+ 主视角 = **11 路**。
  - ⚠️ **映射必须按 role，不能按流号**（顺序不规则：合集=`fight2026011/012`、主视角无解说版=`fight2026013`）。
  - 签名内嵌在该 JSON → **每次进入 fetch 一遍即得新鲜签名**，无需动态签名接口。
- 播放器：原站用 video.js + videojs-contrib-hls；本项目改用 **hls.js**。

### 1.2 弹幕（LeanCloud 实时通信 / IM）
- WS 服务器：`wss://uqaoagyd.im.cn-n1.lncldapi.com/`（LeanCloud IM，cn-n1 节点）。
- 客户端公开密钥（嵌在原站 JS bundle 里）：
  ```
  appId:      UqaoAgYDPakCHxtDiMXVy2Sw-gzGzoHsz
  appKey:     xYO2wtjhri9dJR7Vor8kDFl4
  serverURLs: https://leancloud.robomaster.com   (REGION cn)
  SDK:        leancloud-realtime 5.0.0-rc.8
  ```
- **一个赛区 = 一个 LeanCloud 瞬态会话（chatroom）**，会话 objectId 即赛区的 `chatRoomId`（直接用，无需按名匹配）。
- 单条弹幕 = LeanCloud `TextMessage`（`_lctype:-1`），业务字段挂在 `_lcattrs`：
  ```jsonc
  {
    "_lctext": "东大秦皇岛加油",          // 弹幕正文
    "_lcattrs": {
      "nickname":   "NUAA636",
      "schoolName": "南京航空航天大学",     // 学校
      "position":   "队员",               // 身份：队员 / 老队员 / 校友
      "racingAge":  2,                    // 参赛年限（0/空=无）
      "badge":      "electronicTenth",    // 十周年徽章（""=无）
      "userId": 143020, "sendTime": 1780045966028
    },
    "_lctype": -1
  }
  ```
- **历史**：瞬态聊天室支持 `conversation.queryMessages({limit})`（按时间升序），用于入会时填充列表。
- **匿名发送可行**（实测，经用户授权发过一条）：随机数字 clientId、无签名即可连接并发送，身份字段为自填 payload。

### 1.3 弹幕渲染规则（实测反推）
- **颜色由 `position` 决定，与徽章无关**：
  - `老队员` → 金色 `#FFE180`（原站类名 `chatContent--spcial`，原站把 special 拼错了）。
  - `队员 / 校友`（其余）→ 三文鱼红 `#F5B599`（`chatContent--common`）。
- **身份标签文案**：`racingAge ? `「`{racingAge}年{position}`」` : position`（racingAge=0 时只显示身份，如裸「校友」）。
- **十周年徽章**：`badge==='electronicTenth'` 时显示真徽章图 `rm-static.djicdn.com/documents/73177/f6d5917aea9f21741087685960555448.png`（22×22 contain）。

## 3. 实现的应用

技术栈：React 19 + Vite + TypeScript；Vitest + Testing Library；hls.js；leancloud-realtime。

### 布局
- **第一屏**：左红方 5 机位 ｜ 中主视角(大，含飘屏弹幕) ｜ 右蓝方 5 机位，**全部同时播**。底部控制栏：主视角清晰度、多视角清晰度、弹幕发送条。点机位放大/再点缩回（红蓝各可放大一个）。

## 4. 实测发现的真实 Bug（单测/构建都发现不了，靠实跑才暴露）

1. **`new Realtime` 重复初始化**：React StrictMode（dev 双挂载）导致第二次构造抛 "App already initialized"，弹幕整体连不上 → 把 Realtime 做成模块级单例。
2. **漏了历史拉取**：spec 要求入会拉历史，实现时漏了 → 补 `queryMessages` 回放。
3. **实时弹幕收不到（有历史无实时）**：根因是 **StrictMode 双 client 复用同一 Realtime、共享同一条 WebSocket，第一个 client 被 close 时把共享连接拆了**，存活的 client 收不到 push（历史走 REST 仍能拿）。→ 把连接也做成**按 chatRoomId 缓存的单例 + `close()` no-op**。实测 app 消息数 52→56 实时增长、只读探针同期确认 4 条自然消息，确认恢复。

## 6. 关键技术结论 / 踩坑

- **整套零代理纯前端**：配置(rm-static)、视频(rtmp)、弹幕 WS(LeanCloud) 三处都 `ACAO:*`。
- **流目录一个文件全给齐**：`live_game_info.json` = 直播赛区判定(`liveState`) + 弹幕会话(`chatRoomId`) + 主视角 + 11 机位 + 三档清晰度签名源。
- **LeanCloud 连接要单例**：StrictMode/HMR 会重复 `new Realtime` 抛错；多 client 共享 WS、误关其一会断实时推送。
- **CSS 坑**：`z-index:auto` 不能参与 transition（要给数值才能延迟过渡）；`transform-origin` 不可过渡，必须固定在基础元素；堆叠的红蓝不对称来自 **DOM 顺序**（同 z-index 时晚出现者在上）。
- **live HLS 的后台恢复**：通用「隐藏暂停 / 切回 play」对直播有害，必须**跳回直播前沿**（`liveSyncPosition`）。
- **赛季性**：非直播时段 `liveState===1` 可能不存在；客户端密钥/会话/签名随赛季变动 → 集中放 `config` + 每次进入拉 `live_game_info.json`。
- **验证方法论**：headless 测不了"看起来对不对"，但能精确测"机制对不对"——用 `getComputedStyle` 分时采样验 z-index 时序、`elementFromPoint` 验遮挡、分片请求计数验后台恢复、只读探针验实时。

### 9.4 实现（TDD，新增 16 单测：25 → 41）

**#1 弹幕重连**
- `net/leancloud.ts`：核实实装 `leancloud-realtime` 的 `Event` 枚举（`disconnect/reconnect/offline/online/…`）→ 挂 `disconnect`→「重连中」、`reconnect`→**重 `join()` 瞬态房**（瞬态聊天室重连后成员关系不自动恢复，正是 §5.1「重连后重新 join」的依据）→「已连接」。`DanmakuConnection` 加 `onStatus`。

- `useDanmaku` 暴露 `status`，`App` 顶部 banner 区分「连接中 / 重连中」。

**#2 签名过期重取 + 重试占位 + 直播已结束**
- `NoLiveZoneError`（catalog.ts）：把「无直播赛区」做成可识别终态。
- `singleFlight`（新工具）：N 路同时 403 只重取一次。
- `isSignatureExpiry`（streams.ts）：403/401=签名过期，余=瞬时（就地 `startLoad`）。
- `useCatalog`（新 hook）：loading/live/ended/error 状态机 + 单飞 refresh。过期→换新签名(live)；无赛区→**ended**；网络抖动→保持 live。
- `useHlsPlayer`：fatal 403/401 → 触发重取 + 进 error 态（回调存 ref，避免重建 11 路 hls）；`VideoPlayer` error 态显示「信号中断·重连中」占位。

新测试：`singleFlight`(3)、`leancloud` 缓存单飞/逐出(2)、`useDanmaku` 重连生命周期(1)、`streams`(4)、`catalog` 终态(1)、`useCatalog`(6)。

### 10.3 窄屏响应式（一波三折，记教训）
**Bug**：侧列宽只由高度推导(`(100vh-91px)*16/45`≈288px)且 `flex:none` 不可缩 → 窗口变窄时只压主视角（700px→73px 残条），压到 0 后侧列**穿出视口**（500px 蓝列超屏 +103px、页面溢出 118px）。
- **弯路①** 30vw cap：侧列缩小但底部留黑、未「齐平」→ 被否。
- **弯路②** 「一个框」(机位改 `flex:1` 填高 + 去边框)：引入**裁切** + 丢**圆角** → 被否、回退。
- **定案**（用户给的模型 + 遮罩闸门）：
  - 机位**还原原版**——`aspect-ratio:16/9`(盒=源比例 → `object-fit:cover` 不裁不拉) + `6px` 圆角 + 列间 8px / 机位间 6px 间距。**宽屏本就顶到底、与主视角等高齐平**。
  - 主视角宽 = 框宽 − 2×侧列宽（`flex:1` 吃剩余）；侧列宽由框高定。
  - 窄到 **主视角 < 侧列** → `LiveStage` 用 `ResizeObserver` 盖 **`.stage-cover`「请在大屏幕上观看」** 遮罩；`.stage-row { overflow:hidden }` 兜底裁掉任何溢出（页面零横向溢出、不外穿）。
  - 第二屏 **≤718px**（聊天室 340px 比嵌入页还宽）→ `@media` 改 `flex-direction:column`，嵌入页/聊天室上下堆叠、各满宽、平分页高。
- **教训**：① 「不裁」的前提是**盒子比例 = 视频比例**，别动盒子（`aspect-ratio` 锁源比例时 cover 退化为不裁不拉）；② 「太窄怎么办」用**遮罩闸门**（布局零改动）比**改布局**稳——后者牵一发动全身、连引两次回退。

### 11.1 主视角左上角赛事标题（照搬官方 + 滚动）
把主视角左上原本的「主视角 {清晰度}」纯展示标识，换成当前比赛标题：`超级对抗赛 {赛区} 第N场 {红校} {红队} vs {蓝校} {蓝队}`（实测如「超级对抗赛 北部赛区 第71场 哈尔滨工业大学（威海） HERO vs 应急管理大学 风暴」）。

- **数据源 = 一个本应用此前没拉的接口**：`rm-static.djicdn.com/live_json/current_and_next_matches.json`（CORS `*`、与 `live_game_info` 同域，零代理）。是**数组**，每元素对应一赛区、含 `currentMatch`/`nextMatch`；match 关键字段 `zone.event.title`、`zone.name`、`orderNumber`、`{red,blue}Side.player.team.{collegeName,name}`（赛前 player/team 可能为 null，需空安全）。
- **官方拼接逻辑**从 Nuxt 分包 `pages/live/index` chunk 抠出（`getMatchTitle` + 标题 computed）：`eventName + " " + zoneName + " 第"+orderNumber+"场 " + 红校 红队 + " VS " + 蓝校 蓝队`，任一方学校+队名皆空则省略 " VS "。⚠️ `orderNumber` 是**全局场次号**（68/71…），不是赛区内场次——官方就直接 `第{orderNumber}场`。
- **官方滚动 `handleTextScroll`**：测 `scrollWidth - clientWidth`，>0（溢出）才滚；CSS transition 把文字左移溢出量、约 **25px/s**，滑到底停顿→瞬时归零→循环（**不是无缝跑马灯**；弹幕那套 `@keyframes RightToLeft` 与此独立，勿混）。

### 11.2 弹幕：恒定 px/s + 悬停暂停 + 限上半屏
- **速度模型从「固定时长」改「固定像素速度」**：原 `DURATION_MS` 固定 → 宽屏同样时长走更多像素 = 看起来更快。改 `SPEED_PX_PER_S`，`duration = 固定距离(220vw=2.2×innerWidth px) / 速度` → **任意屏宽同 px/s**（用户要的「不同屏一样快」本质就是恒定 px/s）。值按用户「再慢点」从 240 调到 **160 px/s**。
- **悬停暂停 / 离开继续**：`.dm-fly{pointer-events:auto}`（overlay 整体仍 `none`，点击穿透到视频）+ `.dm-fly:hover{animation-play-state:paused}`。配套把「飞完移除」从 `setTimeout` 改 **`onAnimationEnd`**——否则暂停时定时器照样到点删掉半屏的弹幕；暂停的动画不会触发 `animationend`，于是停住的弹幕不消失，暂停与移除同由动画驱动、自洽。
- **限上半屏**：轨道 `top: 8% + track*8%` → `8/16/24/32/40%`（原 `*16%` 到 72% 已过半屏）。百分比定位 → 任意高度都按比例落上半屏。
- ⚠️ **测试踩坑**：①jsdom 无布局引擎/不跑 CSS 动画，且 React 委托监听收不到合成或原生 `animationend` → **放弃直接测「animationend 移除」**，改测可 robust 验证的两条属性：「**不靠定时器移除**」（fake timer 推进 2 分钟仍在屏 = 暂停安全的前提）+「**时长随屏宽线性**」（= 恒定 px/s）；真悬停/移除靠浏览器实测。②`animationend` 是 React **非离散事件**，其 `setState` 经调度器在**真 macrotask** flush，`vi.useFakeTimers()` 下不跑 → 弃用 fake timers、改给测试消息「未来 sendTime」过 `mountAt` 过滤。
